# Інструкція для командної роботи

Цей документ описує процес командної розробки для проєкту "Генератор хештегів".

## Структура гілок (Branching Strategy)

Проєкт використовує **Git Flow** з такими гілками:

- `main` / `master` — основна гілка зі стабільним кодом (автоматичний деплой на Render)
- `develop` — гілка для розробки (опціонально)
- `feature/*` — гілки для нових функцій (наприклад, `feature/ai-integration`)
- `bugfix/*` — гілки для виправлення помилок (наприклад, `bugfix/login-error`)
- `hotfix/*` — гілки для критичних виправлень у production

## Процес роботи (Workflow)

### 1. Створення нової гілки

```bash
# Оновіть основну гілку
git checkout main
git pull origin main

# Створіть нову гілку для функції
git checkout -b feature/назва-функції

# Або для виправлення помилки
git checkout -b bugfix/опис-помилки
```

### 2. Розробка та коміти

```bash
# Внесіть зміни у код
# ...

# Додайте зміни
git add .

# Створіть коміт з описовим повідомленням
git commit -m "feat: додано інтеграцію з Hugging Face API"

# Або для виправлення
git commit -m "fix: виправлено помилку в генерації хештегів"
```

**Формат комітів (Conventional Commits):**
- `feat:` — нова функція
- `fix:` — виправлення помилки
- `docs:` — зміни в документації
- `style:` — форматування коду
- `refactor:` — рефакторинг
- `test:` — додавання тестів
- `chore:` — інші зміни (залежності, конфіги)

### 3. Push гілки на GitHub

```bash
git push origin feature/назва-функції
```

### 4. Створення Pull Request (PR)

1. Перейдіть на GitHub у репозиторій проєкту
2. Натисніть **"New Pull Request"**
3. Виберіть:
   - **Base branch:** `main`
   - **Compare branch:** `feature/назва-функції`
4. Заповніть опис PR:
   - Що змінено?
   - Навіщо це потрібно?
   - Як це протестувати?
5. Додайте reviewers (якщо є)
6. Натисніть **"Create Pull Request"**

### 5. Code Review

- Перевірте зміни у PR
- Обговоріть зауваження у коментарях
- Внесіть необхідні зміни та push до тієї ж гілки

### 6. Мердж PR

Після схвалення:
- Натисніть **"Merge pull request"**
- Виберіть тип мерджу (зазвичай "Squash and merge" або "Create a merge commit")
- Після мерджу видаліть гілку (опціонально)

## Автоматичний деплой (CI/CD)

Проєкт використовує **GitHub Actions** для автоматичного тестування та деплою:

- При кожному **Push** або **Pull Request** запускаються тести
- При мерджі в `main` автоматично відбувається деплой на Render (якщо налаштовано)

Файл конфігурації: `.github/workflows/deploy.yml`

## Правила кодування

1. **Python:** дотримуйтесь PEP 8
2. **Коментарі:** пишіть коментарі українською або англійською
3. **Імена змінних:** використовуйте зрозумілі назви
4. **Документація:** оновлюйте README.md при додаванні нових функцій

## Вирішення конфліктів

Якщо виникли конфлікти при мерджі:

```bash
# Оновіть вашу гілку
git checkout feature/назва-функції
git pull origin main

# Вирішіть конфлікти у файлах
# ...

# Додайте вирішені файли
git add .
git commit -m "fix: вирішено конфлікти з main"

# Push знову
git push origin feature/назва-функції
```

## Питання та підтримка

Якщо виникли питання:
- Створіть Issue у GitHub
- Обговоріть у Pull Request
- Зверніться до команди

```bash
# 6. Після мерджу

```
