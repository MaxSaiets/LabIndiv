# Інструкція для виконання Індивідуального завдання 2

## Мета
Набуття практичних навичок використання хмарних сервісів штучного інтелекту та засобів командної розробки у процесі створення веб-застосунків.

## Виконані завдання

### ✅ 1. Обрано задачу для модуля ШІ
**Задача:** Генерація коротких резюме текстів для покращення якості генерації хештегів.

**Обґрунтування:** 
- Користувач вводить довгий текст поста
- ШІ генерує коротке резюме, виділяючи ключові ідеї
- На основі резюме генеруються більш релевантні хештеги

### ✅ 2. Підключено сервіс ШІ

**Варіант А: Hugging Face Inference API** (рекомендовано)

**Сервіс:** Hugging Face Inference API  
**Модель:** `facebook/bart-large-cnn` (для англійської мови)  
**Файл реалізації:** `hashtag_app/ai_summarizer.py`

**Як підключити:**
1. Зареєструватися на https://huggingface.co
2. Створити API токен: Settings → Access Tokens → New token
3. Додати токен у змінні оточення: `HUGGINGFACE_API_TOKEN`
4. Детальна інструкція: `HUGGINGFACE_SETUP.md`

**Переваги:**
- Офіційний API з підтримкою токену
- Швидка робота з токеном
- Доступ до тисяч моделей
- Стабільна робота

**Варіант Б: Google Colab з власною моделлю** (альтернатива)

**Сервіс:** Власна модель на Google Colab  
**Файл реалізації:** `hashtag_app/ai_colab.py`

**Як підключити:**
1. Створити Flask API на Google Colab
2. Опублікувати через ngrok
3. Додати URL у змінні оточення: `COLAB_API_URL`
4. Детальна інструкція: `GOOGLE_COLAB_SETUP.md`

**Переваги:**
- Повний контроль над моделлю
- Можливість використовувати власні навчені моделі
- Безкоштовно для тестування

**Примітка:** Застосунок автоматично використовує Colab (якщо налаштовано), інакше — Hugging Face API.

### ✅ 3. Інтегровано модуль ШІ у веб-застосунок

**Зміни в коді:**
- Додано клас `AISummarizer` для роботи з Hugging Face API
- Оновлено API endpoint `/api/generate` для використання ШІ
- Додано поле `ai_summary` в модель `HashtagRequest`
- Оновлено фронтенд для відображення резюме

**Як працює:**
1. Користувач вводить текст поста
2. Можна ввімкнути/вимкнути ШІ (чекбокс)
3. Якщо ШІ ввімкнено → генерується резюме
4. На основі резюме (або оригінального тексту) генеруються хештеги
5. Резюме зберігається в БД

### ✅ 6. Налаштовано командну роботу

**Документація:** `CONTRIBUTING.md`

**Структура гілок:**
- `main` — стабільний код (автоматичний деплой)
- `feature/*` — нові функції
- `bugfix/*` — виправлення помилок
- `hotfix/*` — критичні виправлення

**Процес роботи:**
1. Створення гілки: `git checkout -b feature/назва`
2. Розробка та коміти
3. Push гілки на GitHub
4. Створення Pull Request
5. Code Review
6. Мердж PR

**Приклад PR:**
- Назва: "feat: додано інтеграцію з Hugging Face API"
- Опис: що змінено, навіщо, як тестувати
- Reviewers (якщо є команда)

### ✅ 7. Реалізовано CI/CD-процес через GitHub Actions

**Файл:** `.github/workflows/deploy.yml`

**Що робить:**
- **При Push/Pull Request:**
  - Запускає тести (перевірка імпортів, базові тести)
  - Перевіряє якість коду (flake8)
  - Перевіряє сумісність з Python 3.11

- **При мерджі в main:**
  - Може тригерити деплой на Render (якщо налаштовано)

**Як перевірити:**
1. Push код на GitHub
2. Перейти в репозиторій → вкладка "Actions"
3. Побачити статус виконання workflow

## Додаткові налаштування (опційно)

### Hugging Face API Token (для приватних моделей):
1. Зареєструватися на https://huggingface.co
2. Створити токен
3. Додати у змінні оточення Render: `HUGGINGFACE_API_TOKEN`

### GitHub Secrets (для автоматичного деплою):
1. GitHub → Settings → Secrets and variables → Actions
2. Додати:
   - `RENDER_SERVICE_ID` — ID сервісу на Render
   - `RENDER_API_KEY` — API ключ Render
